# Governance and Updates

## Change classes

### Patch

Typographical corrections, additional tests, source-link repairs, and clarifications that do not change scoring semantics.

### Benchmark version

A new dated benchmark snapshot is required when dimensions, hard gates, aggregation, thresholds, council membership, or output semantics change.

### Lens version

A new immutable lens snapshot is required when evidence, interpretation, confidence, domain coverage, objections, or validity changes.

## Source policy

Use public primary sources where possible: official documentation, repositories, published talks, essays, interviews, and authored posts. Secondary summaries may help discovery but cannot carry a consequential claim when a primary source is available.

Each source reference must record a stable identifier or URL, title, author, publication date when known, retrieval date, evidence class, and the bounded claim it supports.

## Review policy

A benchmark or lens change must pass:

1. schema validation;
2. unsupported-claim checks;
3. public-safety audit;
4. regression fixtures for affected scoring behavior;
5. human review for material changes to public attribution, privacy boundaries, or benchmark semantics.

## Historical integrity

Published snapshots are immutable. Corrections create successor versions and changelog entries. Historical evaluations continue to reference the original inputs unless explicitly migrated as a new evaluation.

## Adding council members

Fame is not sufficient. A candidate needs a documented domain contribution, enough stable public evidence to build a bounded lens, and a clear reason the existing council lacks that perspective. Council changes require a new benchmark version.

## Non-affiliation

The project describes independent analysis of public material. It must not imply participation, endorsement, certification, or approval by any named expert.
